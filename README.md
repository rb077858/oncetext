# OnceText

אתר סטטי לחלוטין (בלי צד שרת משלכם) לשליחת טקסט שנעלם אחרי צפייה.
כל האחסון וכל האכיפה של "כמה פעמים ניתן לצפות" מתבצעים ב-Firebase Firestore,
דרך [חוקי אבטחה](firestore.rules) - אין שום קוד שרת, רק קבצים סטטיים (HTML/CSS/JS)
שמדברים ישירות עם Firestore מהדפדפן.

## איך זה עובד

1. בעמוד הראשי (`index.html`) המשתמש כותב טקסט ובוחר מספר (ברירת מחדל 1, לא ניתן
   לרדת מתחתיו) - כמה אנשים *שונים* יכולים לצפות בטקסט.
2. נוצר מסמך ב-Firestore באוסף `notes` עם השדות: `text`, `maxViews`,
   `consumedCount` (מתחיל מ-0), `createdAt`, `expiresAt`. מוצג קישור לצפייה,
   עם כפתור העתקה וכפתור שליחה בוואטסאפ.
3. מי שפותח את הקישור (`view.html?id=...`) רואה את הטקסט מצויר על גבי `<canvas>`
   (לא כטקסט אמיתי בעמוד) - כדי שלא יהיה ניתן לסמן/להעתיק אותו בקלות. יש גם חסימה
   של תפריט קליק ימני וקיצורי מקלדת נפוצים (שמירה/הדפסה/העתקה).
4. ברגע שהוא **עוזב את הטאב** (עובר לטאב אחר, מחליף אפליקציה, סוגר את הדף - כל מה
   שמפעיל `visibilitychange` ל-`hidden`) נשלחת בקשה ל-Firestore שמגדילה את
   `consumedCount` באחד. זה נשלח עם `fetch(..., {keepalive: true})` כדי שהבקשה
   תושלם גם אם הדף נסגר ממש באותו רגע.
5. חוקי ה-Firestore (`firestore.rules`) חוסמים קריאה (`get`) של מסמך שבו
   `consumedCount >= maxViews`. כלומר ברגע שנוצלו כל הצפיות המותרות, **אף אחד**,
   מכל מכשיר, לא יכול יותר לפתוח את הקישור - גם אם הוא עדיין קיים טכנית ב-DB.
6. בנוסף, בדפדפן הצופה עצמו נשמר סימון ב-`localStorage` (`oncetext_seen_<id>`)
   כדי שאותו אדם ספציפית לא יוכל לצפות שוב באותה הודעה גם אם עוד נשארו "מקומות"
   פנויים (למשל כשההודעה הוגדרה ל-2 צופים).

## הקמה (חד פעמי)

1. צרו פרויקט Firebase חינמי ב-<https://console.firebase.google.com> (תוכנית Spark).
2. בתפריט **Build > Firestore Database** צרו מסד נתונים במצב **Native**, באזור
   קרוב אליכם.
3. ב-**Project settings > General > Your apps** הוסיפו אפליקציית Web, והעתיקו את
   אובייקט הקונפיגורציה (`apiKey`, `authDomain`, `projectId` וכו') לתוך
   `js/firebase-config.js` במקום הערכים `REPLACE_ME`.
4. עדכנו גם את `.firebaserc` עם ה-`projectId` שלכם.
5. התקינו את Firebase CLI (`npm install -g firebase-tools`), התחברו
   (`firebase login`) והריצו מתוך תיקיית הפרויקט:
   ```
   firebase deploy --only firestore:rules
   ```
   זה השלב הקריטי - בלי זה כל מי שרוצה יכול לקרוא/לשנות הודעות של אחרים.
6. לאירוח: אפשר `firebase deploy --only hosting` (מקבלים דומיין
   `your-project.web.app` חינמי), או פשוט להעלות את הקבצים הסטטיים לכל שירות
   אחר (GitHub Pages, Netlify וכו') - זה לא משנה, כי כל הלוגיקה רצה מול Firestore
   ישירות מהדפדפן.
7. **אופציונלי אך מומלץ**: הגדירו מדיניות TTL על השדה `expiresAt` באוסף `notes`,
   כדי שהודעות ישנות (בין אם נוצלו ובין אם לא) יימחקו אוטומטית אחרי 30 יום.
   זה לא ניתן להגדרה מקובץ - צריך להריץ פעם אחת:
   ```
   gcloud firestore fields ttls update expiresAt --collection-group=notes --enable-ttl
   ```
   (או דרך מסך Firestore ב-console: TTL policies).

## מגבלות שכדאי לדעת עליהן

- **"לא ניתן להעתקה" זו הרתעה, לא אבטחה אמיתית.** הטקסט מצויר כתמונה כדי
  שלא יהיה קל לסמן/להעתיק, אבל אין דרך למנוע צילום מסך או צילום עם מצלמה -
  זה נכון לכל שירות דומה שקיים.
- **מרוץ תיאורטי**: הספירה (`consumedCount`) עולה כשצופה *עוזב* את המסך, לא כשהוא
  פותח אותו. המשמעות: אם שני אנשים פותחים בדיוק את אותו קישור בו-זמנית לפני
  שהראשון הספיק לעזוב, שניהם יראו את הטקסט גם אם `maxViews=1`. זו התנהגות
  שנבחרה בכוונה (כדי שההודעה "תיעלם עם היציאה" ולא עם הפתיחה), אבל כדאי לדעת
  עליה.
- **חסימת "אותו אדם" מבוססת `localStorage`** - כלומר דפדפן פרטי/אחר, או ניקוי
  היסטוריה, יכולים לעקוף אותה. החסימה הגלובלית לפי `maxViews` (בחוקי Firestore)
  היא זו שבאמת אוכפת שלא יהיו יותר מהמספר שנקבע.
- אין אימות משתמשים (auth) בכוונה - זה שירות אנונימי לגמרי. אורך ה-ID
  (16 תווים אקראיים) הוא קו ההגנה מפני ניחוש קישורים.
